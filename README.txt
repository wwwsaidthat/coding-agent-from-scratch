Coding Agent from Scratch（LoopCoder）项目说明

一、Git 仓库地址
https://github.com/wwwsaidthat/coding-agent-from-scratch

二、如何运行
环境需要 Python 3.10 或更高版本。项目的 Python 运行时只使用标准库；代码搜索需要 ripgrep，PDF 理解需要 Poppler。在项目根目录执行：

cp .env.example .env

在 .env 中填写自己的 DEEPSEEK_API_KEY。如需联网搜索、图片或 PDF 理解，再填写 QWEN_API_KEY 和对应服务地址。请勿提交包含真实密钥的 .env。

启动网页版：
python3 main.py --web

然后访问 http://127.0.0.1:8765。也可执行无需 API Key 的离线演示：
python3 main.py --demo --workspace /tmp/coding-agent-demo "运行离线工具演示"

运行测试：
python3 -m unittest discover -s tests -v

三、特色功能
本项目不使用 Agent 框架或 Agent SDK，从零实现“模型—工具—结果—模型”自主循环。用户提交 Prompt 后，程序组装系统规则、任务记忆、对话历史和工具定义并请求 DeepSeek。模型返回工具调用时，本地 Agent 负责参数校验与执行，再把 Observation 加入下一轮输入，直到生成最终答案或达到步数限制。

系统提供文件列举、分段读取、精确替换、原子多文件编辑、本地命令执行，以及基于 ripgrep 的文件发现和代码检索。文件编辑强制先读后改，使用文件大小、修改时间和 SHA-256 检测并发冲突；写入前展示红删绿增 Diff，只有用户批准后才会修改工作区。

可视化 Web 界面支持创建、切换和删除多个会话，每个会话独立绑定工作区。复杂任务可建立 Plan，界面逐轮展示 Thought 决策摘要、Action 工具参数、Observation 结果和步骤状态。Trace 持久化保存模型请求、工具输入输出、耗时、错误码、Token 用量和测试结果，便于复现与评估。

上下文管理保留结构化任务检查点和近期完整轨迹，并按 70%/80%/90% 水位依次压缩历史工具结果、旧会话和早期工具轮次。完整大结果按 SHA-256 归档，模型可按需分页回查。可选的通义千问模型负责联网搜索及图片、PDF 理解，查询或文件外传前必须获得用户确认。

项目还实现路径越界防护、敏感文件拦截、命令白名单、执行超时、重复调用检测和最大步数终止，以降低本地 Agent 误操作风险。

模型只负责生成文本和工具调用意图，所有本地操作都由程序注册的工具执行。工具参数使用 JSON Schema 声明并在本地二次校验，失败结果会以统一错误码返回模型，使 Agent 能重新读取文件、修正参数或更换方案，而不是因一次异常立即中断。

会话状态、结构化记忆和执行轨迹采用本地持久化，服务重启后可继续历史任务。测试覆盖工具调度、文件乐观锁、原子编辑、危险路径拦截、上下文裁剪、网页会话恢复、外部能力审批和离线端到端循环。项目同时提供无需真实模型的演示模式，便于评审者快速验证完整 Agent 流程。

四、其它说明
项目默认只监听本机地址，用于本地代码任务，不建议直接暴露到公网。会话、Trace、附件和工具结果保存在本地并被 Git 忽略。当前安全策略属于应用层防护，不等同于容器或操作系统级强隔离，因此不应将不可信项目的工作区指向敏感目录。完整架构、API、工具清单、安全边界和已知限制请查看 README.md 与 docs/architecture.md。
